Comprehensive research and plan for adding 5 new content features: YouTube Video with auto subtitles, News Reading, Podcast, English Games (with XP), and English Book Reading.

## 1. YouTube Video Integration (with Auto Subtitles)

> **Skills**: `ui-ux-pro-max` (player UI, subtitle overlay) · `language-learning-patterns` → `content-difficulty-levels`, `progress-xp-system` · `speech-processing-best-practices` → `tts-caching-strategy`

### Flutter Package

| Package | Version | Key Feature |
|---------|---------|-------------|
| **youtube_player_flutter** | latest | Supports `enableCaption: true` and `captionLanguage` in `YoutubePlayerFlags` |
| **youtube_caption_scraper** | latest | Parse public captions without OAuth (fallback option) |

### API for Subtitles

| API | Free Tier | Use Case |
|-----|-----------|----------|
| **YouTube Data API v3** (`captions.list` + `captions.download`) | 10,000 units/day | List caption tracks, download SRT/VTT, identify auto-generated (trackKind: "ASR") |
| **youtube_caption_scraper** (Dart package) | Unlimited (scraping) | Fallback: parse public captions without API key |

### Detailed Coding Flow

```
SCREEN: CourseDetailScreen (modified)
  │
  ├─ 1. Course model thêm field: `youtubeVideoIds: List<String>`
  │     → Backend trả về danh sách video IDs gắn với khóa học
  │
  ├─ 2. Khi user mở khóa học → hiển thị tab "Video Lessons"
  │     → Mỗi video card: thumbnail + title + duration
  │     → Thumbnail: `https://img.youtube.com/vi/{videoId}/hqdefault.jpg` (free, no API)
  │
  ├─ 3. User tap video → mở YouTubePlayerScreen
  │     ├─ Init YoutubePlayerController(videoId, enableCaption: true, captionLanguage: 'en')
  │     ├─ Gọi Backend: GET /api/youtube/captions/{videoId}
  │     │   └─ Backend: check Redis cache → check DB → call YouTube Data API v3 captions.list
  │     │       └─ Filter trackKind: "ASR" (auto-generated) hoặc "standard"
  │     │       └─ Download SRT/VTT → parse thành List<CaptionSegment>(start, end, text)
  │     │       └─ Cache permanently (captions không đổi)
  │     ├─ Hiển thị subtitle overlay đồng bộ với video timestamp
  │     └─ User có thể: tap từ trong subtitle → tra từ điển (dictionary API)
  │
  ├─ 4. Sau khi xem ≥80% video → gọi POST /api/xp/award {type: "youtube", xp: 15}
  │
  └─ 5. Data Models:
        ├─ CourseVideo(videoId, title, duration, thumbnailUrl, captionAvailable)
        ├─ CaptionSegment(startMs, endMs, text, translatedText?)
        └─ CaptionTrack(id, language, trackKind, isAutoGenerated)
```

> [!NOTE]
> `youtube_player_flutter` has **built-in caption support** via `enableCaption: true`. Custom subtitle overlay chỉ cần khi muốn: tap-to-translate, highlight từ, hoặc hiển thị song ngữ.

## 2. News Reading Feature

> **Skills**: `ui-ux-pro-max` (article reader, quiz UI) · `language-learning-patterns` → `content-difficulty-levels` (CEFR grading), `adaptive-weak-points` (vocabulary), `progress-xp-system` · `speech-processing-best-practices` → `tts-neural-voices` (article TTS)

### Recommended APIs (used by apps like News In Levels, Readle, FluentU)

| API | Free Tier | Features | Best For |
|-----|-----------|----------|----------|
| **NewsAPI.org** | 100 req/day | 80,000+ sources, keyword search, language filter | Development & MVP |
| **NewsData.io** | 200 req/day | 84 countries, 58 languages, comprehensive filtering | Multi-language news |
| **World News API** | 500 req/day | Global coverage, 30-day historical data | High volume needs |
| **New York Times API** | 500 req/day (4000/month) | High-quality English content, article search | Premium English content |
| **The News API** | Free (unlimited) | 40,000+ sources, JSON format | Budget-friendly option |

### Recommended: **NewsAPI.org** (development) → **NewsData.io** (production)

### Detailed Coding Flow

```
SCREEN: NewsListScreen
  │
  ├─ 1. Khi mở screen → gọi GET /api/news?level={cefr}&category={cat}&page={n}
  │     └─ Backend flow:
  │         ├─ Check Redis: api:news:en:{cat}:{date} → HIT → return cached
  │         ├─ Check DB: api_cache_entries WHERE key = 'news:en:{cat}:{date}'
  │         ├─ MISS → Check quota (newsapi) → quota OK?
  │         │   ├─ YES → Call NewsAPI.org: /v2/top-headlines?language=en&category={cat}
  │         │   │         → Parse response → filter articles with content
  │         │   │         → AI Service: grade_text(content) → assign CEFR level (A1-C2)
  │         │   │         → Store Redis (TTL 1h) + PostgreSQL + return
  │         │   └─ NEAR LIMIT (≥70%) → chỉ fetch nếu DB cache > 6h tuổi
  │         │   └─ QUOTA EXHAUSTED → return stale DB data + header X-Data-Freshness
  │         └─ Flutter nhận response → filter theo user's CEFR level
  │
  ├─ 2. Hiển thị danh sách articles:
  │     ├─ Card: title + source + image + CEFR badge (A1/A2/B1...) + publish time
  │     ├─ Color-coded CEFR: A1=green, A2=lime, B1=yellow, B2=orange, C1=red, C2=purple
  │     └─ Pull-to-refresh (respect quota: chỉ refresh nếu cache > 30 phút)
  │
  ├─ 3. User tap article → mở NewsDetailScreen:
  │     ├─ Full article content with paragraph breaks
  │     ├─ Highlighted vocabulary: AI-detected difficult words underlined
  │     │   └─ Tap word → bottom sheet: definition + IPA + audio (Free Dictionary API)
  │     │       └─ "Save to Vocabulary" button → lưu SQLite + sync backend
  │     ├─ 🔊 Listen button: gửi content → AI Service TTS (Piper) → just_audio playback
  │     ├─ Reading progress bar (scroll-based)
  │     └─ Khi đọc xong (scroll ≥90%) → show "Take Quiz" button
  │
  ├─ 4. Quiz flow:
  │     ├─ Gọi AI Service: generate_quiz(article_content, level, count=5)
  │     ├─ 5 câu hỏi: comprehension + vocabulary + grammar (multiple choice)
  │     ├─ Submit → calculate score → POST /api/xp/award {type: "news", xp: 15, score}
  │     └─ Show results + correct answers + explanations
  │
  └─ 5. Data Models:
        ├─ NewsArticle(id, title, content, source, imageUrl, publishedAt, cefrLevel, category)
        ├─ SavedWord(word, definition, ipa, audioUrl, sourceArticleId, savedAt)
        └─ NewsQuiz(articleId, questions: List<QuizQuestion>, score, completedAt)
```

### Detailed Coding Flow

```
SCREEN: YouTubeExploreScreen
  │
  ├─ 1. Trang chính hiển thị:
  │     ├─ Curated Channels carousel (hardcoded channel IDs, prefetch 2x/day)
  │     │   └─ Channel card: avatar + name + subscriber count
  │     ├─ "Trending for English Learning" section (prefetched, cached 12h)
  │     ├─ Category tabs: Grammar, Pronunciation, Vocabulary, IELTS, Daily English
  │     └─ Search bar (debounced 500ms, min 3 chars)
  │
  ├─ 2. Search flow (QUAN TRỌNG: search.list tốn 100 units → phải cache!):
  │     ├─ User nhập query → debounce 500ms
  │     ├─ Check local SQLite: youtube_search:{query_hash} (TTL 24h)
  │     ├─ MISS → gọi GET /api/youtube/search?q={query}&maxResults=10
  │     │   └─ Backend: check quota (youtube, cost=100)
  │     │       ├─ NORMAL (≤70%) → call API → cache Redis 6h + DB 12h
  │     │       ├─ WARNING (70-90%) → call API only if no cached results exist
  │     │       ├─ CRITICAL (90-100%) → return cached only + suggest curated content
  │     │       └─ BLOCKED (100%) → return curated content only
  │     └─ Display results: thumbnail + title + channel + duration + view count
  │
  ├─ 3. User tap video → YouTubePlayerScreen:
  │     ├─ Same as Section 1 (Course YouTube integration)
  │     ├─ Additional: "Related Videos" section (videos.list, 1 unit each → cheap)
  │     ├─ "Add to Playlist" → lưu vào user's custom learning playlist (local DB)
  │     └─ Share button
  │
  ├─ 4. Tap channel → ChannelDetailScreen:
  │     ├─ Channel info: banner + description + video count
  │     ├─ Videos list (playlists.list → playlistItems.list, 1-3 units)
  │     └─ "Follow" button → nhận notifications khi có video mới (local check 1x/day)
  │
  └─ 5. Data Models:
        ├─ YouTubeVideo(videoId, title, channelId, channelName, thumbnailUrl,
        │              duration, viewCount, publishedAt, captionAvailable)
        ├─ YouTubeChannel(channelId, name, avatarUrl, subscriberCount, videoCount)
        ├─ UserPlaylist(id, name, videoIds: List<String>, createdAt)
        └─ YouTubeSearchCache(queryHash, results: JSON, cachedAt)
```

> [!WARNING]
> `search.list` tốn **100 units** mỗi request. Với budget 8,000 units/day, chỉ có thể search **80 lần/ngày**. Phải cache aggressively và ưu tiên hiển thị curated content.

### Game 1: Word Scramble (Xếp chữ)

**Kỹ năng rèn:** Spelling, Vocabulary recognition

```
┌─────────────────────────────────────────┐
│  Word Scramble        ⏱ 00:45    7/10  │
│─────────────────────────────────────────│
│                                         │
│    💡 Hint: "A place where you live"    │
│                                         │
│    ┌───┐ ┌───┐ ┌───┐ ┌───┐ ┌───┐      │
│    │ O │ │ E │ │ S │ │ U │ │ H │  ← drag tiles
│    └───┘ └───┘ └───┘ └───┘ └───┘      │
│                                         │
│    Answer: [H][O][U][S][E]              │
│    ────── ────── ────── ────── ──────   │
│                                         │
│    ⭐ Streak: 5 correct in a row!       │
│    XP: +12 (base 10 + streak bonus 2)  │
└─────────────────────────────────────────┘
```

**Gameplay chi tiết:**
- Backend tạo 10 words phù hợp CEFR level → shuffle letters
- User kéo thả (drag) tiles vào vị trí đúng hoặc tap theo thứ tự
- Timer 60s cho 10 từ (A1-A2: 90s, B1-B2: 60s, C1-C2: 45s)
- Mỗi từ đúng: base XP + streak bonus (3+ liên tiếp = +2 XP/từ)
- Sai: hiện hint → sai lần 2 → hiện 1 chữ cái đầu → sai lần 3 → skip
- XP: 10-30 tùy độ dài từ (3-4 chữ = 10, 5-6 = 15, 7+ = 20-30)
- **Offline:** words lưu sẵn trong SQLite theo CEFR, không cần API

### Game 2: Fill in the Blank (Điền từ)

**Kỹ năng rèn:** Grammar, Vocabulary in context, Reading comprehension

```
┌─────────────────────────────────────────┐
│  Fill in the Blank     ⏱ 01:20   3/8   │
│─────────────────────────────────────────│
│                                         │
│  "She _______ to school every day."     │
│                                         │
│  ┌──────────┐    ┌──────────┐          │
│  │  A. go   │    │ B. goes ✓│  ← tap   │
│  └──────────┘    └──────────┘          │
│  ┌──────────┐    ┌──────────┐          │
│  │ C. going │    │ D. gone  │          │
│  └──────────┘    └──────────┘          │
│                                         │
│  ✅ Correct! +15 XP                     │
│  📖 "goes" - Present Simple, 3rd person │
│     She/He/It + V-s/es                  │
└─────────────────────────────────────────┘
```

**Gameplay chi tiết:**
- AI Service sinh câu hỏi dựa trên CEFR level + grammar rules đang học
- VD A1: Present Simple → "She ____ (go) to school" → goes
- VD B2: Conditionals → "If I ____ (know), I would have told you" → had known
- 8 câu/round, mỗi câu 4 lựa chọn, chọn 1 đáp án đúng
- Timer: 15s/câu (tăng áp lực, rèn phản xạ)
- Đúng → hiện giải thích ngữ pháp ngắn gọn (grammar tip)
- Sai → highlight đáp án đúng + giải thích tại sao sai
- XP: 15 (easy) / 25 (medium) / 40 (hard) per round
- **API:** Cần AI Service generate questions (cache 24h, batch generate)

### Game 3: Matching Game (Nối từ)

**Kỹ năng rèn:** Vocabulary, Word-Definition association, Speed recall

```
┌─────────────────────────────────────────┐
│  Matching Game         ⏱ 00:32   4/6   │
│─────────────────────────────────────────│
│                                         │
│  ┌──────────┐      ┌──────────────┐    │
│  │ enormous │──────│ very large   │ ✅  │
│  └──────────┘      └──────────────┘    │
│  ┌──────────┐      ┌──────────────┐    │
│  │ purchase │  ?   │ a short trip │    │
│  └──────────┘      └──────────────┘    │
│  ┌──────────┐      ┌──────────────┐    │
│  │ journey  │      │ to buy       │    │
│  └──────────┘      └──────────────┘    │
│  ┌──────────┐      ┌──────────────┐    │
│  │ ancient  │      │ very old     │    │
│  └──────────┘      └──────────────┘    │
│                                         │
│  ⏱ Time bonus: +5 XP (under 30s!)     │
└─────────────────────────────────────────┘
```

**Gameplay chi tiết:**
- 2 cột: bên trái = English words, bên phải = definitions (shuffled)
- User tap từ bên trái → tap definition bên phải → nối thành cặp
- Đúng: cặp biến mất với animation ✅ + sound
- Sai: cả 2 shake đỏ → reset, trừ 2 XP
- Difficulty scaling:
  - A1-A2: 4 cặp, từ đơn giản (big→large, happy→glad)
  - B1-B2: 6 cặp, synonyms/definitions (enormous→very large)
  - C1-C2: 8 cặp, idioms/collocations
- Variations (random mỗi lần chơi):
  - Word ↔ Definition | Word ↔ Vietnamese translation
  - Word ↔ Image | Word ↔ Synonym | Word ↔ Antonym
- Time bonus: hoàn thành trước 50% time → +5 XP bonus
- XP: 10 (4 cặp) / 18 (6 cặp) / 25 (8 cặp)
- **Offline:** word pairs lưu SQLite, không cần API

### Game 5: Grammar Quiz (Trắc nghiệm ngữ pháp)

**Kỹ năng rèn:** Grammar accuracy, CEFR grammar progression

```
┌─────────────────────────────────────────┐
│  Grammar Quiz          ⏱ 00:52   6/10  │
│─────────────────────────────────────────│
│                                         │
│  📝 Topic: Past Simple vs Present       │
│     Perfect                              │
│                                         │
│  "I _______ him since last Monday."     │
│                                         │
│  ○ A. didn't see                        │
│  ○ B. don't see                         │
│  ● C. haven't seen  ← selected         │
│  ○ D. wasn't seeing                     │
│                                         │
│  ┌──────────┐                           │
│  │ ✅ Check │                           │
│  └──────────┘                           │
│                                         │
│  ✅ Correct! Since + Present Perfect    │
│  "Since" chỉ khoảng thời gian từ quá   │
│  khứ đến hiện tại → dùng have/has + V3 │
│  📊 Grammar mastery: Past vs PP → 78%  │
└─────────────────────────────────────────┘
```

**Gameplay chi tiết:**
- AI sinh 10 câu theo grammar topic phù hợp CEFR + weak points của user
- Topics organized by CEFR:
  - A1: To be, Present Simple, There is/are, Possessives
  - A2: Past Simple, Future (will/going to), Comparatives

### 8.2.1 Graduated Threshold System (Near-Limit Protection)

```
┌──────────────────────────────────────────────────────────────────────────┐
│                     QUOTA THRESHOLD FLOW                                │
│                                                                          │
│  Request arrives → QuotaManager.check_status(api_name, cost)            │
│                                                                          │
│  ┌─────────────────────────────────────────────────────────────────┐     │
│  │  usage / budget    │  Status    │  Behavior                    │     │
│  ├─────────────────────────────────────────────────────────────────┤     │
│  │  0% - 69%          │  NORMAL    │  Fetch from API normally     │     │
│  │  70% - 89%         │  WARNING   │  Only fetch if NO cache      │     │
│  │                    │            │  exists (stale OK → skip)    │     │
│  │  90% - 99%         │  CRITICAL  │  Only fetch if request is    │     │
│  │                    │            │  HIGH priority (user-init.)  │     │
│  │                    │            │  + NO cache at all           │     │
│  │  100%              │  BLOCKED   │  NEVER fetch. Serve stale    │     │
│  │                    │            │  cache or return 429         │     │
│  └─────────────────────────────────────────────────────────────────┘     │
│                                                                          │
│  Priority Levels:                                                        │
│  ├─ HIGH:   User-initiated search, user-requested content               │
│  ├─ MEDIUM: Auto-load (screen open, scroll pagination)                  │
│  └─ LOW:    Prefetch, background refresh, related content               │
│                                                                          │
│  At WARNING: block LOW priority requests                                 │
│  At CRITICAL: block LOW + MEDIUM priority requests                       │
│  At BLOCKED: block ALL requests                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

> [!CAUTION]
> Threshold percentages are based on **Internal Budget**, not the API's actual limit. This provides a safety buffer. E.g., NewsAPI actual limit = 100, budget = 80, WARNING at 56 (70% of 80) = chỉ mới dùng 56% API limit thật.

```python
class APICacheService:
    """3-layer cache: Redis → PostgreSQL → External API
    
    Flow: check_cache → check_quota_threshold → decide_fetch_or_serve_stale
    """
    
    async def get_or_fetch(
        self, 
        cache_key: str,           # e.g. "news:en:technology:2026-02-24"
        api_name: str,            # e.g. "newsapi"
        fetch_fn: Callable,       # actual API call function
        priority: Priority = Priority.MEDIUM,  # request priority
        redis_ttl: int = 3600,    # Redis TTL in seconds
        db_ttl: int = 86400,      # DB "freshness" TTL
    ) -> CacheResult:
        # 1. Check Redis (hot cache)
        cached = await self.redis.get(f"api:{cache_key}")
        if cached:
            return CacheResult(data=json.loads(cached), source="redis", is_stale=False)
        
        # 2. Check PostgreSQL (persistent cache)
        db_entry = await self.db.query(APICacheEntry).filter_by(key=cache_key).first()
        if db_entry and not db_entry.is_expired(db_ttl):
            # Fresh DB cache → warm Redis and return
            await self.redis.setex(f"api:{cache_key}", redis_ttl, db_entry.data)
            return CacheResult(data=json.loads(db_entry.data), source="db", is_stale=False)
        
        # 3. Check quota threshold BEFORE calling external API
        quota_status = await self.quota_manager.check_status(api_name)
        
        if quota_status == QuotaStatus.BLOCKED:
            # 100%+ used → NEVER call API
            if db_entry:
                return CacheResult(data=json.loads(db_entry.data), source="db_stale", is_stale=True)
            raise QuotaExhaustedError(api_name, self.quota_manager.get_reset_time())
        
        if quota_status == QuotaStatus.CRITICAL and priority != Priority.HIGH:
            # 90-99% used → only HIGH priority gets through
            if db_entry:
                return CacheResult(data=json.loads(db_entry.data), source="db_stale", is_stale=True)
            # No cache AND not high priority → reject
            raise QuotaNearLimitError(api_name, "CRITICAL", "Only user-initiated requests allowed")
        
        if quota_status == QuotaStatus.WARNING and priority == Priority.LOW:
            # 70-89% used → block LOW priority (prefetch, background)
            if db_entry:
                return CacheResult(data=json.loads(db_entry.data), source="db_stale", is_stale=True)
            # No cache at all → allow even LOW (user should see something)
        
        # 4. Quota OK → Fetch from external API
        result = await fetch_fn()
        await self.quota_manager.record_request(api_name)
        
        # 5. Store in both cache layers
        data_json = json.dumps(result)
        await self.redis.setex(f"api:{cache_key}", redis_ttl, data_json)
        await self.db.upsert(APICacheEntry(
            cache_key=cache_key, api_name=api_name, data=data_json
        ))
        
        return CacheResult(data=result, source="api", is_stale=False)
```

#### [NEW] `backend-service/app/services/quota_manager.py`

```python
from enum import Enum

class QuotaStatus(Enum):
    NORMAL = "normal"       # 0-69% → all requests allowed
    WARNING = "warning"     # 70-89% → block LOW priority
    CRITICAL = "critical"   # 90-99% → only HIGH priority
    BLOCKED = "blocked"     # 100%+ → all requests blocked

class Priority(Enum):
    HIGH = "high"       # User-initiated: search, tap-to-read
    MEDIUM = "medium"   # Auto-load: screen open, pagination
    LOW = "low"         # Background: prefetch, related content

class QuotaManager:
    """Track API usage with graduated near-limit thresholds."""
    
    # Internal budget (lower than actual API limit for safety buffer)
    LIMITS = {
        "newsapi": 80,         # actual: 100
        "newsdata": 160,       # actual: 200
        "youtube": 8000,       # actual: 10,000 (units)
        "podcastindex": 500,   # actual: unlimited (respectful limit)
        "openlibrary": 1000,   # actual: unlimited
        "gutenberg": 200,      # actual: unlimited
        "dictionary": 2000,    # actual: unlimited
        "wordsapi": 2000,      # actual: 2,500
    }
    
    # Threshold percentages
    WARNING_THRESHOLD = 0.70   # 70% of budget
    CRITICAL_THRESHOLD = 0.90  # 90% of budget
    
    async def check_status(self, api_name: str, cost: int = 1) -> QuotaStatus:
        """Check current quota status with graduated thresholds."""
        key = f"quota:{api_name}:{date.today()}"
        current = int(await self.redis.get(key) or 0)
        budget = self.LIMITS[api_name]
        usage_ratio = (current + cost) / budget
        
        if usage_ratio >= 1.0:
            return QuotaStatus.BLOCKED
        elif usage_ratio >= self.CRITICAL_THRESHOLD:
            return QuotaStatus.CRITICAL
        elif usage_ratio >= self.WARNING_THRESHOLD:
            return QuotaStatus.WARNING
        return QuotaStatus.NORMAL
    
    async def record_request(self, api_name: str, cost: int = 1):
        """Record API usage. Returns updated QuotaStatus."""
        key = f"quota:{api_name}:{date.today()}"
        new_count = await self.redis.incrby(key, cost)
        await self.redis.expire(key, 86400)  # Auto-expire at midnight
        
        # Log warning thresholds
        budget = self.LIMITS[api_name]
        ratio = new_count / budget
        if ratio >= self.CRITICAL_THRESHOLD:
            logger.warning(f"🔴 CRITICAL: {api_name} at {ratio*100:.0f}% ({new_count}/{budget})")
        elif ratio >= self.WARNING_THRESHOLD:
            logger.info(f"⚠️ WARNING: {api_name} at {ratio*100:.0f}% ({new_count}/{budget})")
        
        return await self.check_status(api_name, cost=0)
    
    async def get_usage(self, api_name: str) -> dict:
        """Get detailed usage info including threshold status."""
        key = f"quota:{api_name}:{date.today()}"
        used = int(await self.redis.get(key) or 0)
        budget = self.LIMITS[api_name]
        status = await self.check_status(api_name, cost=0)
        return {
            "api": api_name,
            "used": used,
            "budget": budget,
            "remaining": max(0, budget - used),
            "usage_percent": round(used / budget * 100, 1),
            "status": status.value,
            "warning_at": int(budget * self.WARNING_THRESHOLD),
            "critical_at": int(budget * self.CRITICAL_THRESHOLD),
        }
    
    async def get_all_usage(self) -> list:
        """Get usage for all APIs (for admin dashboard)."""
        return [await self.get_usage(api) for api in self.LIMITS]
    
    def get_reset_time(self) -> str:
        """Return time until daily quota resets (midnight UTC)."""
        now = datetime.utcnow()
        reset = (now + timedelta(days=1)).replace(hour=0, minute=0, second=0)
        remaining = reset - now
        return f"{remaining.seconds // 3600}h {(remaining.seconds % 3600) // 60}m"
```

### 8.4 Flutter-Side Local Cache

#### [NEW] `flutter-app/lib/core/services/local_cache_service.dart`

```dart
class LocalCacheService {
  static const _tableName = 'api_cache';
  
  // TTL per content type
  static const ttlConfig = {
    'news': Duration(hours: 2),
    'youtube': Duration(hours: 24),
    'podcast': Duration(hours: 6),
    'book': Duration(days: 7),
    'dictionary': Duration(days: 30),  // Words rarely change
  };

  Future<T?> getOrFetch<T>(String key, String type, Future<T> Function() fetchFn) async {
    // 1. Check local SQLite cache
    final cached = await _db.query(_tableName, where: 'key = ?', whereArgs: [key]);
    if (cached.isNotEmpty) {
      final entry = cached.first;
      final age = DateTime.now().difference(DateTime.parse(entry['updated_at']));
      if (age < ttlConfig[type]!) {
        return jsonDecode(entry['data']) as T;
      }
    }
    
    // 2. Fetch from backend (which handles Redis/DB/API cascade)
    try {
      final result = await fetchFn();
      await _upsertCache(key, type, jsonEncode(result));
      return result;
    } catch (e) {
      // 3. Serve stale cache on network error (offline-first)
      if (cached.isNotEmpty) return jsonDecode(cached.first['data']) as T;
      rethrow;
    }
  }
}
```

| **Podcast Audio** | Never (stream) | — | — | Optional download | User can download for offline |
| **Books Metadata** | Never | 24h | 7d | 7d | Stable content |
| **Book Content** | Never | — | Permanent | Permanent | Full text never changes |
| **Dictionary** | Never | 7d | Permanent | 30d | Definitions are immutable |

### 8.6 Quota Exhaustion Fallback Chain

```
Request comes in → Check Quota → Quota OK?
  ├─ YES → Check Redis → Redis Hit? → Return cached
  │               └─ No → Check DB → DB Hit (fresh)? → Return & warm Redis
  │                           └─ No → Call External API → Store in Redis + DB → Return
  │
  └─ NO (Quota Exhausted) → Check Redis → Hit? → Return cached (may be stale)
                                └─ No → Check DB → Hit? → Return stale + warn header
                                            └─ No → Return 429 with retry_after
```

> [!TIP]
> **Key principle: Never show an empty screen.** Even with exhausted quotas, serve stale cached data with a subtle "Last updated X hours ago" indicator. Only show errors when there is genuinely no cached data available.
